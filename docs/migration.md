# 版本迁移与回退政策

## 应用升级前

1. 退出 FilmLab，确认最后一次项目保存完成。
2. 复制完整 `.filmlab` 目录；项目备份不替代外部备份。
3. 保留原安装器、版本号和 `SHA256SUMS`，再安装同一 `appId` 的新版。Windows 原位升级和 macOS 应用替换保留用户数据。
4. 首次用新版本打开重要项目时先使用只读模式检查来源重连、校准快照和预览；确认后再允许迁移写回。

## 项目 schema

当前项目 schema 为 v8。v1-v7 项目先迁移到内存并只读展示，用户明确确认后才备份原 `project.json` 并原子写入 v8。损坏的主文件只能从最近有效备份只读恢复，确认前不得覆盖现场。比当前应用更新的 schema 必须拒绝写入，不能猜测降级。

v8 保存文件名、扩展名、尺寸、修改时间和完整 SHA-256，不保存源绝对路径；本机私有索引负责自动重连。迁移或复制到另一台机器后，扫描源目录以内容身份重连。项目引用的校准配置以快照随项目移动。

## 回退

项目一旦由新版确认迁移并保存，不保证旧版可写。需要回退时，关闭应用，恢复升级前完整项目副本和匹配的旧安装器；不要用旧版覆盖新版项目。应用卸载默认保留用户数据，因此卸载不是回滚，也不是隐私擦除。

跨平台迁移必须用各平台安装包和对应 sidecar。Windows 验收不能替代 macOS/Linux 结果。色彩可信度、解码 fingerprint 或校准 schema 变化属于显式迁移边界，必须重新验证设备匹配，不能因项目能打开就继承“颜色准确”结论。
