# FilmLab

FilmLab 是面向个人胶片翻拍/扫描的负像还原工作台:导入负像图片,自动检测片基、反转密度、中和橙罩,并还原为可调色的正像。

```text
扫描/翻拍负片(TIFF / JPEG / PNG)
→ 线性透射率(16-bit TIFF 保持全精度)
→ 画水平参考线校正任意角度 / 自动去空角 / 裁剪
→ 片基检测(默认自动上包络估算,可框选未曝光边缘实测)
→ 相对密度 D = -log10(T / Tbase)
→ Dmin/Dmax 锚点 + 多候选中性轴 / 单调通道曲线(自动中和橙罩)
→ 10^D 反转 → 自动白平衡(灰世界中位数)或手动色温
→ 曝光 / 对比度 / 高光压缩 / 饱和度
→ 白点归一化 → sRGB 编码
→ 16-bit TIFF / JPEG 导出
```

## 核心流程

1. **导入底片**:支持 8/16 位 TIFF、JPEG、PNG。同一文件对话框可选择一张或多张，也可选择文件夹(非递归扫描支持格式,按文件名排序)。16 位无 ICC 的 TIFF 按已线性化的扫描数据读取(扫描仪 raw 惯例);8 位文件按显示编码的 sRGB 执行逆传递函数。带 ICC 的 TIFF 会被明确拒绝,避免色彩管理悄悄破坏 16 位精度——请先用 ImageMagick 等工具转换。
2. **片基检测**:默认使用自动估算(三通道联合透射上包络,置信度上限 0.65,界面会提示它不能替代实测片基);也可以在画面上框选一段未曝光片基边缘获得实测值(中位数 + MAD 抗离群)。裁掉边缘后自动估算无法唯一确定真实 Dmin,建议保留一条片基边再框选。
3. **密度反转**:相对密度按通道取 `D = -log10(T/Tbase)`,以 `10^D - 1` 反转为正像。开启"自动中和"后,画面样本以确定性空间哈希拆成 80% 训练、20% 验证；训练集同时估计两轮 Theil–Sen 中性轴和 MAD/Tukey 加权 PCA 主轴，验证集选择残差更低的仿射种子。随后按 12 个影调段拟合 PAVA 单调通道曲线，用于吸收三个染料层在 toe、中间调和 shoulder 的非线性响应差异。曲线只有在验证综合残差改善至少 10%、90 分位不明显恶化且至少一个影调端改善 10% 时才启用；否则依次回退到最佳仿射轴、ROI/高密度锚点或单位校正。曲线额外修正限制为 ±0.35D，外推斜率限制为 0.25–4。预饱和仍在仿射与曲线归一化之后、指数反转之前应用。该近似依据彩色负片各染料层具有独立特性曲线的感光测量原理，参见 [Kodak Basic Photographic Sensitometry](https://www.kodak.com/content/products-brochures/Film/Basic-Photographic-Sensitometry-Workbook.pdf)。
4. **几何与调色**:沿画面中应为水平的边缘拖一条参考线即可校正任意角度，旋转后自动取最大无空角矩形；旧裁剪、片基和中性选区会因坐标系改变而清除。曝光(EV)、绕 0.18 中灰的对数域对比度、高光软拐点压缩、饱和度全部在线性光域完成。自动白平衡继续使用稳健灰世界中位数；关闭后可在 2500–10000K 调整手动色温，5500K 为不改变颜色的中性点。自动白点把中央高光百分位归一化到显示白，sRGB OETF 只在最终量化时应用。
5. **导出**:同一配方在导出时以原始全分辨率重算。单帧导出 TIFF 为 16-bit sRGB Deflate(自有编码器);JPEG 为质量 95、4:4:4 的 8-bit sRGB。两种格式都先写入同目录临时文件再原子发布，且均不含 ICC/XMP，交付编码按未标记 sRGB 约定。

## 公测安全边界与恢复

- 单个源文件最大 1 GiB，最长边 32,768 像素，总像素不超过 1 亿，预计 Float32 解码栅格不超过 1.2 GB；单卷最多 500 帧。TIFF 最多 65,536 个 strip，单 strip 解码上限 256 MiB，IFD 链、标签数组、偏移和实际解压长度也会校验。
- 主进程把所有 renderer IPC 参数视为不可信输入：导入模式、opaque frame ID、完整 Recipe、ROI、数组长度和导出格式都会重新解析。无效请求、损坏 TIFF、内存不足和磁盘写满会转换为可读错误，不把系统路径回传到诊断信息。
- 导出前检查目标目录可访问、剩余空间满足预计输出加 64 MiB 余量；文件先写同目录临时文件，成功后再原子替换。删除帧会同步释放主进程路径注册；导出结束、窗口销毁和重新导入会清理取消状态及无效路径。
- 最近会话自动保存在本机 Electron 用户数据目录，包含源路径、逐帧配方和当前帧，用于异常退出恢复。应用不上传这些数据；详见 [PRIVACY.md](PRIVACY.md)。“关于”中的复制诊断只包含版本、系统、Worker 状态、帧数和去路径化错误状态。

## CPU 加速与缓存

- 预览由一个长驻 Web Worker 处理，UI 线程只接收最终 RGBA 并绘制。Worker 同时只执行一项任务；连续拖动滑杆时只保留最新配方和 revision，当前帧优先于缩略图，不会累积过时任务。
- `NegativeSession` 把管线分为几何、片基/密度/去色罩、反转、白平衡和最终调色层。曝光、对比度、高光及饱和度只重算最后一层；自动白平衡开启时，手动色温变化不会使缓存失效。
- 预览源最多缓存三帧，只有当前帧保留派生缓存，Worker 预算为 192 MiB。Worker 不可用或异常时自动回退同步 CPU 路径，公式与结果不变。
- 全分辨率导出在主进程外的协调 Worker 中完成。大于等于 100 万像素时使用 `min(4, availableParallelism - 2)` 个像素 Worker，按 128 行动态分块；小图或仅一个可用线程时仍在后台单线程执行。整卷继续逐帧处理，以约束内存和保持帧边界取消语义。
- 密度、反转、增益、调色及 8/16 位编码共享同一组区间内核；最终调色与编码融合，并显式保留原有 Float32 舍入边界。子线程异常会停用并行池并用无状态基准管线重算，协调 Worker 最多自动重启一次。
- 本版本有意不使用 GPU、WebGL 或 WebGPU，以最终 8/16 位编码值逐字节一致为首要约束。实现方式参照 [electron-vite 多线程打包](https://electron-vite.org/guide/dev#multi-threading)与 [Node.js Worker Threads](https://nodejs.org/api/worker_threads.html)。

## 整卷工作流

- 导入整卷(多选文件或文件夹)后,左侧胶片条显示每帧缩略图(缩略图按该帧配方即时渲染为正像);点选帧即可用全部工具单独调整,每帧配方独立。
- 「应用到整卷」把当前帧完整配方复制给所有未跳过的帧;每帧可单独标记跳过(不导出)或移除。
- 「整卷→TIFF/JPEG」选择输出文件夹后顺序导出:每帧全分辨率重算、原子写出,同名自动加 `-2` 后缀;进度实时显示,可随时取消(取消前已完成的文件保留);单帧失败(损坏/ICC 拒绝)记录在摘要中,不中断其余帧。

## 开发与验证

```powershell
npm install
npm run check      # typecheck + 全部测试
npm run benchmark  # 冷/热预览与 24MP CPU 导出基准；仅记录，不设 CI 时间断言
npm run dev        # 启动工作台
npm run build      # 产物构建
npm run dist:win   # 打包安装程序
```

正式 Windows 包必须通过 `npm run dist:win` 生成：该命令要求代码签名证书环境变量，安装器、主程序和卸载器由发布流水线验证 Authenticode。无证书的本地结构验收须显式使用 `npm run dist:win:unsigned`，其产物不得分发。发布流程、哈希与回滚步骤见 [docs/RELEASE.md](docs/RELEASE.md)。

测试用 `node --test` 直接运行 TypeScript:核心数学(片基/密度/锚点/PCA/单调曲线/反转/调色/编码/几何)、含 30% 彩色离群点与 toe/shoulder 响应的端到端合成负片反转、训练/验证过拟合回退、缓存失效边界、快速百分位等价性、1/2/4 分块的 8/16 位逐字节一致性、真实文件解码及导出回读校验。

## 架构

```text
src/core/        纯函数处理核心,无 Electron 依赖,域标签强制
src/main/        Electron 主进程:解码、导出协调 Worker、像素 Worker、IPC
src/preload/     contextBridge 白名单桥接(无源文件路径暴露)
src/renderer/    React 界面:画布预览、框选交互、控件面板
```

- 像素域通过 `Raster` 的域标签(`transmission-linear` / `relative-density` / `scene-linear-rgb` / `display-linear`)在每一阶段边界强制校验,显示编码值不可能进入对数密度。
- 渲染进程只收到降采样后的像素载荷与文件名,源文件绝对路径留在主进程;导出由主进程按配方重解码全分辨率并原子写盘。
- 预览计算在 Web Worker 中使用共享核心和分层缓存(110 ms 防抖);片基采样失败时自动回退到自动估算并提示。渲染线程不再同步执行正常预览还原。

## 边界

- 不承诺默认模式的相机/扫描仪颜色准确性;白平衡与中和是单帧、全局、无色卡的实用估计。主体颜色严重占优、混合光或染料层信息缺失时会回退或只能给出折中结果,精确颜色仍需要色卡标定(本版本未内置)。
- 本次公测明确不以真实底片验收集作为放行条件。自动片基、去色罩与白平衡尚未覆盖所有胶片乳剂、扫描仪和翻拍设备组合；严重主体偏色、混合光、染料层退化、老化褪色和厂商特殊扫描曲线属于已知限制。用户可在明确自愿的前提下提交去隐私样片，但不是使用或发布条件。
- 无 ICC 的 16-bit TIFF 会按线性扫描数据解释，但不同扫描软件可能写入未标记的非线性值；这类文件会导致密度和色彩判断偏差，应在导入前确认扫描软件输出约定或转换为已知线性数据。
- 支持条带布局的 8/16 位整数 RGB/灰度 TIFF(无压缩/Deflate/LZW/PackBits,含逐分量水平差分还原);分块、浮点、YCbCr、JPEG 压缩 TIFF 会明确拒绝并提示转换方式。
- 内存:导出把像素变换就地复用在一幅共享 Float32 RGB 帧中，另保留解码/几何源和最终编码缓冲；整卷不并行驻留多帧。任意角度几何期间会短暂持有旋转目标，超大文件仍需留意可用内存。
- 输出不嵌入 ICC/XMP,交付值即 sRGB。
